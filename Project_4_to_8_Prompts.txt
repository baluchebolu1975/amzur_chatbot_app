PROJECT 4 — MEMORY WINDOW
====================================================================
1) CONTEXT
- Existing app already has users, threads, and messages with persistent chat.
- Every chat must remember the previous 5 conversations in the same chat before answering.
- No disruptive changes to existing auth/chat flows.

2) GOAL
- Implement fixed memory retrieval and context injection for chat generation.
- Before every answer, include the previous 5 conversations from the same chat thread as context.

3) RULES
- Keep backward compatibility with all existing chat endpoints.
- Additive changes only; avoid breaking schema unless strictly required.
- Use a fixed memory size of 5 previous conversations only.
- Do not introduce user-facing memory mode selection for Project 4.
- A conversation means one prior user message plus its assistant reply in the same thread.
- If fewer than 5 prior conversations exist, use all available prior conversations.
- Enforce token budget before LLM call.
- Validate thread ownership and authorization.
- Add tests for retrieval logic and edge cases.

4) OUTPUT
- Backend service: previous-5-conversations selector + prompt context assembler.
- API integration that injects the last 5 conversations before each answer.
- Integration into message generation pipeline.
- No frontend control required for Project 4 unless needed only for display/debugging.
- Unit + integration tests.
- Acceptance proof: run test output + sample request/response.
